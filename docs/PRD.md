# PaperScholar — 产品需求文档 (PRD)

> 版本: v1.0 | 日期: 2026-02-27 | 状态: 草案

---

## 1. 项目概述

**PaperScholar** 是一个专为科研人员打造的 AI 学术图表生成与编辑平台。融合 PaperBanana 的多Agent生成流水线、AutoFigure 的 SVG 迭代优化、AutoFigure-Edit 的矢量化编辑能力，并配备完整的用户管理和多Provider API 管理系统。

**核心定位**: 帮助科研人员快速生成、编辑和精修高质量学术图表。

**非商业用途**: 本项目为开源学术工具，无商业化计划。

---

## 2. 目标用户

| 角色 | 场景 |
|------|------|
| **科研人员** | 论文写作中需要生成方法论示意图、流程图 |
| **论文作者** | 需要将数据可视化为高质量统计图表 |
| **数据分析师** | 需要专业的柱状图、折线图、饼图等 |
| **系统管理员** | 部署和管理平台，审核API申请 |

## 3. 功能需求

### Phase 1 (MVP) — 核心功能

#### F1.1 统一多Provider LLM客户端
> 优先级: P0 | 所有AI功能的基础设施

| 需求 | 说明 |
|------|------|
| F1.1.1 多Provider支持 | OpenAI兼容格式（OpenRouter/自定义endpoint）、Google Gemini原生格式、Anthropic格式 |
| F1.1.2 Chat/Image模型分离配置 | Chat模型和Image模型各自独立配置 provider/base_url/api_key/model_name |
| F1.1.3 默认+自定义配置 | 提供默认配置（一键使用），也支持用户自定义修改 |
| F1.1.4 多Key负载均衡 | 用户配置多个API Key时，支持 Round-Robin / Random 轮询调用 |
| F1.1.5 错误自动切换 | 某个Key调用失败时自动切换到下一个可用Key |
| F1.1.6 重试机制 | 指数退避重试，可配置最大重试次数 |

#### F1.2 用户管理系统
> 优先级: P0

| 需求 | 说明 |
|------|------|
| F1.2.1 注册/登录 | 邮箱+密码注册，支持邮箱验证码 |
| F1.2.2 角色权限 | 管理员 / 普通用户 两种角色 |
| F1.2.3 JWT认证 | Token-based 认证，7天有效期 |
| F1.2.4 用户信息管理 | 查看/修改个人信息 |

#### F1.3 API Key 管理
> 优先级: P0

| 需求 | 说明 |
|------|------|
| F1.3.1 系统API申请 | 用户可申请使用系统预置的API Key |
| F1.3.2 管理员审核 | 系统API申请需管理员审核通过后才可使用 |
| F1.3.3 自有API配置 | 用户可填写自己的API Key（支持多个） |
| F1.3.4 API Key验证 | 自有API填写后发送测试请求验证有效性 |
| F1.3.5 Chat/Image分离 | Chat模型和Image模型可分别配置不同的API Key/URL/模型 |
| F1.3.6 API Key脱敏展示 | 前端仅显示Key的前8位+后4位 |

#### F1.4 学术图表生成（核心Pipeline）
> 优先级: P0 | 参照PaperBanana五Agent架构

| 需求 | 说明 |
|------|------|
| F1.4.1 输入 | Method Section内容（Markdown推荐） + Figure Caption |
| F1.4.2 参数配置 | Pipeline模式、检索设置、候选数量、宽高比、Critic轮数 |
| F1.4.3 参考图检索 | 内置PaperBananaBench数据集 + 支持用户上传参考图 |
| F1.4.4 Pipeline模式 | vanilla / planner / planner_stylist / planner_critic / full 五种模式 |
| F1.4.5 多候选并行生成 | 支持同时生成多个候选图（最多20个） |
| F1.4.6 Critic迭代 | 可配置迭代轮数（1-5轮） |
| F1.4.7 结果展示 | 网格展示候选图，支持下载单张或批量ZIP |

#### F1.5 实时交互反馈
> 优先级: P0 | 解决PaperBanana无反馈的痛点

| 需求 | 说明 |
|------|------|
| F1.5.1 SSE实时推送 | 通过Server-Sent Events推送Pipeline状态 |
| F1.5.2 阶段状态显示 | 显示当前正在执行的Agent名称和阶段 |
| F1.5.3 中间产物预览 | Planner输出的文本描述、Visualizer的阶段图片、Critic的反馈意见实时推送给前端 |
| F1.5.4 进度指示 | 显示整体进度百分比和预计剩余时间 |
| F1.5.5 Pipeline Evolution | 展示从初始生成到最终结果的演化过程 |

#### F1.6 管理员后台
> 优先级: P1

| 需求 | 说明 |
|------|------|
| F1.6.1 用户管理 | 查看/管理所有用户，修改角色 |
| F1.6.2 API申请审核 | 审核用户的系统API使用申请 |
| F1.6.3 系统配置 | 配置默认模型、系统API Key、SAM3模式等 |
| F1.6.4 用量统计 | 查看用户API调用次数/Token消耗 |
| F1.6.5 系统公告 | 发布/管理系统公告 |

### Phase 2 — 结构化数据图表 + 交互优化

#### F2.1 结构化数据图表生成
> 优先级: P1

| 需求 | 说明 |
|------|------|

| F2.1.2 图表类型 | 柱状图、折线图、饼图、散点图、热力图等 |

| F2.1.5 样式自定义 | 支持配色方案、字体、图例位置等自定义 |

> 优先级: P1

| 需求 | 说明 |
|------|------|
| F2.2.1 历史记录 | 保存用户的生成历史，支持查看和重新生成 |
| F2.2.2 收藏功能 | 用户可收藏满意的生成结果 |

### Phase 3 — 矢量化编辑 + 精修增强

#### F3.1 图表编辑与矢量化
> 优先级: P2 | 参照AutoFigure-Edit

| 需求 | 说明 |
|------|------|
| F3.1.1 图片上传 | 上传已有学术图表（PNG/JPG） |
| F3.1.2 SAM3分割 | 自动检测图标区域（本地GPU / API模式，管理员选择） |
| F3.1.3 去背景 | RMBG2自动去除图标背景 |
| F3.1.4 SVG模板生成 | LLM多模态生成SVG模板 + 语法验证修复 |
| F3.1.5 图标替换 | 将去背后的图标替换到SVG占位符 |
| F3.1.6 在线SVG编辑 | 集成svg-edit编辑器，支持所见即所得编辑 |
| F3.1.7 风格迁移 | 上传参考图像，模仿其视觉风格 |
| F3.1.8 SAM3 API模式 | 用户使用API模式需自行提供fal.ai/Roboflow API Key |

#### F3.2 精修与增强
> 优先级: P2

| 需求 | 说明 |
|------|------|
| F3.2.1 图片精修 | 上传候选图 + 描述修改需求 → Image模型精修 |
| F3.2.2 分辨率上采样 | 支持上采样到2K/4K |
| F3.2.3 AI美化 | code2prompt模式AI增强美化 |
| F3.2.4 部分精修 | 选择图表的局部区域进行精修（如有可能） |

## 4. 参考图数据集管理

| 需求 | 说明 |
|------|------|
| 内置数据集 | 预置PaperBananaBench数据集（diagram + plot） |
| 用户上传 | 用户可上传自己的参考图，用于检索匹配 |

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| **部署** | Docker Compose 一键部署到Linux服务器 |
| **架构** | 前后端分离（React/Next.js + Python FastAPI） |
| **数据库** | PostgreSQL |
| **缓存** | Redis（会话/任务状态/API Key缓存） |
| **安全** | JWT认证、API Key加密存储、CORS配置、速率限制 |
| **并发** | 支持多用户同时使用，Pipeline异步执行 |
| **可扩展** | 模块化设计，易于添加新的LLM Provider和Pipeline Agent |
